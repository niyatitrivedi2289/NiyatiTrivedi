Get started with the Payments API

The Payments API is the heart of Access Worldpay. It takes you from authorization through settlement, supports recurring agreements, and exposes everything you need to refund or query a transaction. The walkthrough below sets up your client and runs through the canonical first request.

Set your headers

Every request to the Payments API carries two headers: Authorization identifies your merchant account, and Content-Type tells us which API version you are speaking.

http 
Authorization: Basic {your_credentials}
Content-Type: application/vnd.worldpay.payments-v6+json
Header Description
Authorization required Identifies the merchant within Access Worldpay. Send the base64-encoded form of your username:password pair on every request, prefixed with Basic .
Content-Type required Selects the API version and resource shape. Required whenever the request includes a body — that is, POST and PUT calls.
Idempotency-Key Recommended for state-changing requests. Replays with the same key return the original response.
Note Replace {your_credentials} with your base64-encoded Basic Auth username and password. To get your Access Worldpay credentials, contact your Implementation Manager.

Versioning

This walkthrough covers requests and responses for version 6 of the Payments API. Check the API reference for the full surface across all versions we currently support.

Query the Payments root resource

Querying the service:payments root returns the action links and resources that are available to your account. Don't hard-code child paths — always navigate from links returned in the root.

Request

GET https://try.access.worldpay.com/payments 
// curl example
curl -X GET "https://try.access.worldpay.com/payments" \
  -H "Authorization: Basic {your_credentials}"

Response

json 
{
  "_links": {
    "payments:authorize":           { "href": "/payments/authorizations" },
    "payments:migrateRecurring":    { "href": "/payments/recurring/migrations" },
    "payments:migrateCardOnFile":   { "href": "/payments/cardOnFile/migrations" },
    "payments:recurringMandate":    { "href": "/payments/recurring/mandates" },
    "curies": [{ "name": "payments", "href": "/rels/payments/{rel}", "templated": true }]
  }
}
Tip Use the action links returned to send your next request. Do not hardcode URIs — they may change between versions.

Resources

The root response surfaces every action your account can take. Pick the one you need and follow its href.

Action link Description
payments:authorize Authorize a payment once.
payments:migrateRecurringAuthorize Authorize and make an existing recurring payment agreement compliant with the stored credential mandate.
payments:migrateCardOnFileAuthorize Authorize and bring a new or existing card-on-file agreement to Access Worldpay.
payments:migrateCardOnFileSale Authorize and settle customer-initiated card-on-file payments.
payments:recurringMandate You can't send requests to this resource directly. It is used by our Verifications API to make recurring/CardOnFile authorizations MIT/CIT compliant.

Link caching

Tip When you make a request within Access Worldpay, cache the response you receive. Re-fetching links on every call is wasteful and adds latency.
